# Project constitution

This entry point records the shared minimum rules; existing owner-approved product requirements and domain storage contracts remain authoritative.

1. Work is tracked by a company ticket with a verifiable done definition.
2. Facts require file, test or measurement evidence. Unknown and failed are explicit states.
3. Preserve product data. Do not silently rewrite requirements or domain data formats.
4. Keep credentials, private data and environments out of source control.
5. No automatic publication, deletion, real-money action or model replacement.
6. Publication policy: `github_existing`. Projects without an existing GitHub remote remain local; never create a remote for them.
7. Read the shared company documentation standard and record handovers with evidence.
